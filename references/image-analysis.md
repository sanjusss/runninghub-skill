# 图片识别与结果检查

生成任务完成后经常需要"看一眼"结果（检查是否命中提示词、挑选最佳图、向用户描述内容）。两条路线：

## 1. 使用当前环境的图片查看能力（首选，不消耗 RunningHub 余额）

当前环境能够直接读取图片时：

1. 运行生成命令时传入用户工作区中的绝对 `--outdir`，下载图片后 JSON 里会有 `localPath`
2. 使用环境已有的图片查看工具读取 `localPath`，并明确检查问题，例如：

```
请识别 /path/to/project/outputs/runninghub/1900000000000000001_0.png 的内容：
画面主体是什么？是否符合提示词"a tiny robot painting a wall mural"？
用一句中文总结，并给出 1-10 分的符合度评分。
```

3. 根据检查结果决定交付、换 seed 重跑或调整提示词。只有用户明确要求并且环境允许时，才把图片检查交给子代理

适合的场景：单图质量检查、多图对比选优、向无法查看图片的用户描述结果。

## 2. RunningHub 图生文模型（备选，通过 API 完成）

环境不能读取图片时，查标准模型目录是否提供 image-to-text 类端点（需要企业级-共享 Key，以实时查询为准）：

```bash
rh.py models --task image-to-text      # 有输出才可用
rh.py models --kw 图生文               # 按关键词兜底搜索
```

若两类查询都为空，说明此路线当前不可用，回到方案 1。

## 实践建议

- **检查生成是否符合预期再交付**：文本到图像经常偏差，先识别再决定重试（改 seed/加强提示词）还是交付
- **多结果挑选**：工作流常输出多张（results 数组），全部下载后逐张对比评分
- 识别输入图（用户上传的素材）也用同样方法，帮助构造更准的提示词（如"图里是什么风格/主体/颜色"）
