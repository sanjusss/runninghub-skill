# 图片识别与结果检查

生成任务完成后经常需要"看一眼"结果（检查是否命中提示词、挑选最佳图、向用户描述内容）。两条路线：

## 1. 具备视觉能力的子代理（首选，不消耗 RunningHub 余额）

当前 agent 环境支持派生子代理且子代理具备视觉能力时（例如 ZCode 子代理 + GLM-5.3-Flash 等视觉模型）：

1. 确保图片已在本地（`rh.py` 的 `--outdir` 已自动下载，JSON 里有 `localPath`）
2. 派生一个子代理（Agent 工具），把图片绝对路径与具体问题写进任务描述，例如：

```
子代理任务：请识别 /tmp/out/1900000000000000001_0.png 的内容：
画面主体是什么？是否符合提示词"a tiny robot painting a wall mural"？
用一句中文总结，并给出 1-10 分的符合度评分。
```

3. 子代理读取图片（多数 agent 的文件读取工具支持 PNG/JPG）并返回描述，主代理据此决定：交付用户 / 换 seed 重跑 / 调整提示词

适合的场景：单图质量检查、多图对比选优（把多张路径都给子代理）、向无图能力的对话描述结果。

## 2. RunningHub 图生文模型（备选，API 内闭环）

环境没有视觉子代理时，查标准模型目录是否提供 image-to-text 类端点（需企业级-共享 Key；**当前官方目录已下线该类端点，以实时查询为准**）：

```bash
python3 scripts/rh.py models --task image-to-text      # 有输出才可用
python3 scripts/rh.py models --kw 图生文               # 按关键词兜底搜索
```

若两类查询都为空，说明此路线当前不可用，回到方案 1。

## 实践建议

- **检查生成是否符合预期再交付**：文本到图像经常偏差，先识别再决定重试（改 seed/加强提示词）还是交付
- **多结果挑选**：工作流常输出多张（results 数组），全部下载后让子代理对比评分选最佳
- 识别输入图（用户上传的素材）也用同样方法，帮助构造更准的提示词（如"图里是什么风格/主体/颜色"）
- 已验证案例：修改 nodeInfoList 提示词后生成"红跑车山路"图，子代理识别结果与提示词一致——参数替换链路端到端可靠
